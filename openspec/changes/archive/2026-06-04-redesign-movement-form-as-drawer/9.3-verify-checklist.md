# Verify manual — Tarea 9.3

Checklist priorizado por riesgo para verificar paridad de comportamiento del form tras la migración a `useMovementForm` (Group 7). La extracción movió ~28 `useState` + ~9 handlers + un dispatcher de submit de ~290 líneas; ese es el área de regresión real. La JSX no se tocó — los chequeos visuales son de baja prioridad.

## Tier 1 — Submit dispatcher (cada tab, modo create)

- [ ] **Ingreso** → se crea, la lista se refresca
- [ ] **Gasto desde efectivo/banco** → se crea
- [ ] **Gasto desde tarjeta de crédito, 1 cuota** → dispara `registerCardPurchase` (una sola transaction)
- [ ] **Gasto desde tarjeta de crédito, 3 cuotas** → dispara `registerInstallments` (parent + 3 children)
- [ ] **Transferencia** entre dos cuentas → se crea, ambos balances actualizan
- [ ] **Ajuste con Sumar** → el balance sube
- [ ] **Ajuste con Restar** → el balance baja
- [ ] **Cambio de moneda** ARS↔USD → se crea una sola transaction dual-currency

## Tier 2 — Modo edición (cada branch del `submitEdit`)

- [ ] Abrir detalle de ingreso/gasto → "Editar" → cambiar descripción → guardar → se actualiza
- [ ] Editar transferencia → se actualiza correctamente
- [ ] Editar ajuste → el signo (dirección) se preserva
- [ ] Editar exchange → ambas patas actualizan
- [ ] Editar **parent de cuotas** (desde el detalle de una compra en N cuotas) → solo categoría/descripción editable

## Tier 3 — Flujos compuestos (los add-ons de mayor riesgo)

- [ ] Gasto + **reintegro (a cuenta)**: toggle on, monto, guardar → aparece la fila de reintegro
- [ ] Gasto en tarjeta + **reintegro (en resumen)**: toggle on, guardar → reintegro de tipo statement
- [ ] Gasto + **reintegro % auto-calc**: ingresar porcentaje + tope, verificar que el monto se recalcula
- [ ] Gasto + **compartido** (con hogar de 2 miembros): toggle on, mover slider de split, guardar → se crean los shared splits
- [ ] Cuotas + compartido: cada cuota recibe su share
- [ ] Ingreso + **Repetir → mensual** → se crea la recurrencia después del movimiento
- [ ] Gasto + **Repetir → personalizado (cada N unidades)** → el intervalo custom persiste

## Tier 4 — "+ Otro" (la UX más sensible)

- [ ] Click "+ Otro" → se guarda con éxito, el drawer queda abierto, **monto + descripción se limpian**, cuenta/fecha/tipo/moneda se mantienen, el foco vuelve al input de monto

## Tier 5 — Cascadas y UI en vivo (regresiones en setters)

- [ ] Cambiar tab a Transferencia → la cuenta de crédito desaparece del picker
- [ ] Cambiar tab → categoría/subcategoría se limpian, cuotas vuelve a 1
- [ ] Cambiar tab a Cambio de moneda → destino default a la misma cuenta que el origen
- [ ] Seleccionar cuenta de crédito → moneda salta a ARS, cuotas se reinicia
- [ ] Cambiar cuenta origen → "credit-to" del reintegro default a banco de la misma institución
- [ ] Tipear descripción → blur → si hay match en historial, aparece chip **Sugerida**; click → la categoría se llena
- [ ] Tipear descripción sin historial → blur → el hint pedagógico aparece después de elegir una categoría
- [ ] Presionar **⌘+Enter** en cualquier lado del form → envía

## Tier 6 — Chequeos secundarios

- [ ] Saldo negativo: gasto > disponible muestra warning (solo cash/bank, no credit)
- [ ] Preview de ajuste muestra balance viejo vs. nuevo
- [ ] Breakdown de cuotas: "N cuotas de $X" — el residuo cae en la primera cuota
- [ ] ESC cierra popovers sin cerrar el drawer

## Stop conditions (regresiones reales)

Si cualquiera de estas falla, hay una regresión:

- Submit tiene éxito pero dispara la acción equivocada (tab equivocado → mutator equivocado)
- Submit se ejecuta pero no aparece la fila en la lista (cache invalidation rota)
- Las cascadas no disparan (cambiar tab deja eligible-accounts stale)
- "+ Otro" cierra el drawer en vez de mantenerlo abierto

Chequeos visuales (spacing, colores, íconos): la JSX no se tocó en la migración del Group 7. Si algo se ve raro, es preexistente.
